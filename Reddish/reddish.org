  I was confused about what *SRVHOST* should be - turns out, in general, it 
  indicates a rogue server which we control; it is necessary for some exploits
  like in this case, the exploit requires a rogue master redis server; so i
  tried setting *SRVHOST* to the kali ip; but the exploit didn't work.
  Gemini explanation:
  #+begin_src 
  In Metasploit, SRVHOST stands for Server Host.
  When a Metasploit exploit module requires an SRVHOST, it means the module
  needs to spin up a temporary local server on your own attacking machine (or
  a server you control) to host a payload or an exploit file that the victim
  machine will fetch.
  In the context of the Redis master-slave replication exploit you are
  running:
  1. What it does: Metasploit needs to act as the "rogue" Redis master server.
  2. Why it needs SRVHOST: The SRVHOST parameter tells Metasploit which
     network interface IP address on your attacking machine it should bind to
     so it can listen for the incoming replication connection from the victim
     Redis server.
  #+end_src
